# Практическое занятие: Web Scanning средствами Kali Linux

## Тема занятия

**Разведка и сканирование веб-приложений с использованием Kali Linux**

Продолжительность: **80–90 минут**

Формат: демонстрация преподавателя + самостоятельная практическая работа студентов.

Учебная цель:

```text
https://demo.testfire.net
```

Это специально подготовленное демонстрационное веб-приложение Altoro Mutual, предназначенное для обучения и тестирования средств анализа безопасности.

> Все действия в рамках занятия выполняются только против специально предназначенной учебной цели. Не следует переносить эти команды на сторонние сайты без разрешения владельца.

# 4. Что такое Web Scanning — 5 минут

Перед командами важно объяснить разницу.

На предыдущих занятиях при помощи Nmap мы отвечали на вопросы:

```text
Какой компьютер существует?
Какой IP у компьютера?
Какие порты открыты?
Какие сетевые службы работают?
```

Теперь мы предполагаем, что веб-сервис уже найден.

Нас интересует:

```text
Как сервер отвечает?

Какой HTTP-код возвращается?

Как называется сайт?

Какой Web Server используется?

Какие технологии используются?

Какие дополнительные страницы существуют?

Есть ли потенциальные проблемы безопасности?
```

Показать общую модель:

```text
192.168.x.x
      ↓
   Port 80/443
      ↓
     HTTP
      ↓
 Web Application
      ↓
   Scanning
```

# 5. Этап 1 — первоначальная HTTP-разведка

Продолжительность: **10 минут**

## 5.1 Проверяем доступность сайта

Открыть:

```bash
curl -I $TARGET
```

Обратить внимание студентов на первую строку ответа.

Например:

```text
HTTP/1.1 200 OK
```

Объяснить основные HTTP-коды:

```text
200 → запрос успешно обработан

301 → постоянное перенаправление

302 → временное перенаправление

400 → неправильный запрос

401 → требуется авторизация

403 → сервер понял запрос, но запрещает доступ

404 → ресурс не найден

500 → внутренняя ошибка сервера
```

---

## 5.2 Посмотреть полный ответ

```bash
curl $TARGET
```

Студенты увидят HTML-код страницы.

Объяснить:

```text
Browser
   ↓
HTTP Request
   ↓
Web Server
   ↓
HTTP Response
   ↓
HTML
```

Браузер просто отображает полученный HTML более удобно.

---

## 5.3 Посмотреть подробности соединения

```bash
curl -v $TARGET
```

Показать студентам:

```text
DNS resolution
TCP connection
TLS
HTTP request
HTTP response
headers
```

Не требуется разбирать каждую строку — задача показать, сколько информации скрывается за обычным открытием сайта.

### Скриншот №1

Студенты выполняют:

```bash
curl -I $TARGET
```

и сохраняют результат для отчёта.

# 6. Этап 2 — httpx-toolkit

Продолжительность: **10 минут**

Объяснить назначение:

> `httpx-toolkit` используется для быстрой разведки HTTP/HTTPS-сервисов и получения основной информации о цели.

Запускаем:

```bash
httpx-toolkit \
-u $TARGET \
-sc \
-title \
-server \
-td \
-ip
```

Разбираем аргументы:

```text
-u       Target URL

-sc      HTTP status code

-title   название HTML-страницы

-server  Web Server

-td      technology detection

-ip      IP сервера
```

---

## Обсуждение результата

Задать студентам вопросы:

```text
Какой HTTP-код вернулся?

Как называется страница?

Какой IP используется?

Удалось ли определить сервер?

Какие технологии определены?
```

Показать важную мысль:

```text
IP address
   ↓
Web Server
   ↓
Application
   ↓
Technology Stack
```

### Скриншот №2

```bash
httpx-toolkit -u $TARGET -sc -title -server -td -ip
```

# 7. Этап 3 — Fingerprinting с WhatWeb

Продолжительность: **10 минут**

## Что такое Fingerprinting

Объяснить:

> Fingerprinting — попытка определить технологии, используемые веб-приложением, на основе его ответов.

Например:

```text
Apache
nginx
IIS
PHP
ASP.NET
Java
jQuery
Bootstrap
WordPress
Drupal
Cookies
HTTP Headers
```

Запускаем:

```bash
whatweb $TARGET
```

После этого:

```bash
whatweb -v $TARGET
```

`-v`:

```text
verbose
```

то есть более подробный вывод.

---

## Сравниваем результаты

На доске:

```text
httpx-toolkit
      ↓
быстрая общая разведка

WhatWeb
      ↓
более подробный fingerprinting технологий
```

Важно объяснить:

> Если инструмент определил технологию, это ещё не означает, что результат на 100% правильный.

Например:

```text
HTTP Header
Server: Apache
```

может быть изменён администратором.

### Скриншот №3

```bash
whatweb $TARGET
```

# 8. Этап 4 — Content Discovery через ffuf

Продолжительность: **20 минут**

Это одна из основных частей занятия.

## 8.1 Проблема

Пользователь открывает сайт и видит:

```text
/
├── index.jsp
├── login.jsp
└── contact.jsp
```

Но сервер потенциально может содержать:

```text
/
├── index.jsp
├── login.jsp
├── contact.jsp
├── admin/
├── images/
├── backup/
├── test/
├── api/
└── old/
```

При этом ссылки на некоторые директории могут отсутствовать.

---

# 9. Что такое Wordlist

Показать:

```bash
ls /usr/share/wordlists/
```

Далее:

```bash
ls /usr/share/wordlists/dirb/
```

Например:

```bash
head /usr/share/wordlists/dirb/common.txt
```

Студенты увидят:

```text
admin
administrator
backup
images
login
test
uploads
...
```

Объяснить:

> ffuf последовательно подставляет эти слова в URL и смотрит, как отвечает сервер.

---

# 10. Первый запуск ffuf

Поскольку используется публичная учебная система, обязательно ограничиваем скорость запросов.

```bash
ffuf \
-w /usr/share/wordlists/dirb/common.txt \
-u $TARGET/FUZZ \
-rl 5
```

Объяснить:

```text
-w
```

wordlist.

```text
-u
```

URL.

```text
FUZZ
```

место, куда будут подставляться слова.

```text
-rl 5
```

не более пяти запросов в секунду.

Показать процесс:

```text
FUZZ = admin

https://demo.testfire.net/admin
```

потом:

```text
FUZZ = images

https://demo.testfire.net/images
```

и так далее.

---

# 11. Анализ результатов ffuf

Например:

```text
images      [Status: 301]
login       [Status: 200]
admin       [Status: 403]
```

Объяснить студентам:

```text
200
ресурс существует и доступен

301 / 302
ресурс существует, но происходит перенаправление

401
ресурс существует, требуется аутентификация

403
ресурс существует, но доступ запрещён

404
ресурс отсутствует
```

Особенно подчеркнуть:

```text
403 ≠ ресурс отсутствует
```

Наоборот, это может свидетельствовать о существовании интересующего пути.

---

# 12. Фильтрация ffuf

Чтобы оставить интересующие HTTP-коды:

```bash
ffuf \
-w /usr/share/wordlists/dirb/common.txt \
-u $TARGET/FUZZ \
-mc 200,204,301,302,307,401,403 \
-rl 5
```

Объяснить:

```text
-mc
```

означает:

```text
match status codes
```

Допустим, найден путь:

```text
/images
```

Проверяем:


Либо открываем:


### Скриншот №4

Студент сохраняет результат `ffuf`, содержащий найденные пути.

# 14. Этап 5 — Nuclei

Продолжительность: **15–20 минут**

Теперь переходим от:

```text
Reconnaissance
```

к:

```text
Vulnerability Scanning
```

Сначала объяснить, что делает Nuclei.

Схема:

```text
Nuclei template
      ↓
HTTP Request
      ↓
Web Server
      ↓
HTTP Response
      ↓
Template conditions
      ↓
Finding
```

# 15. Проверяем шаблоны Nuclei

```bash
nuclei -update-templates
```

Объяснить:

> Nuclei использует большое количество готовых шаблонов, описывающих признаки различных неправильных конфигураций и известных проблем.

---

# 16. Первый запуск Nuclei

Используем ограничение скорости:

```bash
nuclei \
-u $TARGET \
-rl 5
```

Не нужно пытаться подробно разобрать каждую найденную запись.

Главная задача — понять формат.

---

# 17. Фильтруем результаты

```bash
nuclei \
-u $TARGET \
-severity low,medium,high \
-rl 5
```

Разобрать:

```text
info
low
medium
high
critical
```

Условная шкала:

```text
info
 ↓
low
 ↓
medium
 ↓
high
 ↓
critical
```

---

# 18. Главное правило работы со сканерами

Объяснить отдельно.

Если Nuclei показывает:

```text
[medium] some-finding
```

неправильно говорить:

```text
Сайт уязвим.
```

Правильнее:

```text
Сканер обнаружил потенциальную проблему.
```

Дальше требуется:

```text
Finding
   ↓
Understand
   ↓
Verify
   ↓
Determine impact
```

Причины ложных результатов:

```text
нестандартная конфигурация;

изменённый ответ приложения;

ошибка определения версии;

защитный прокси;

WAF;

устаревший шаблон;

неполная информация.
```

### Скриншот №5

```bash
nuclei -u $TARGET -severity low,medium,high -rl 5
```

# 20. Разница между инструментами

| Инструмент | Основной вопрос |
|---|---|
| `curl` | Как сервер отвечает на HTTP-запрос? |

# 27. Итог занятия

Студенты должны запомнить не набор отдельных команд, а общий подход:

```text
Discover
   ↓
Identify
   ↓
Enumerate
   ↓
Scan
   ↓
Verify
```

В применении к веб-приложению:

```text
curl
 ↓
httpx-toolkit
 ↓
WhatWeb
 ↓
ffuf
 ↓
Nuclei
 ↓
Manual analysis
```

На следующем занятии логичным продолжением будет уже не автоматическое сканирование, а **ручной анализ веб-приложения через Burp Suite**:

```text
HTTP Request / Response
        ↓
Proxy
        ↓
GET / POST
        ↓
Headers
        ↓
Cookies
        ↓
Parameters
        ↓
Burp Repeater
```

То есть текущий урок отвечает на вопрос **«что мы можем обнаружить автоматически?»**, а следующий — **«как исследовать найденное вручную?»**.
