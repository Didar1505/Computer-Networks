# Практическая работа
## Настройка Static NAT, Dynamic NAT и PAT в корпоративной сети

**Дисциплина:** Компьютерные сети  
**Программное обеспечение:** Cisco Packet Tracer  

## Цель работы

Научиться  создавать корпоративную сеть, настраивать маршрутизацию и использовать различные технологии преобразования сетевых адресов:

- **Static NAT** — статическое преобразование IP-адресов.
- **Dynamic NAT** — динамическое преобразование IP-адресов с использованием пула.
- **PAT (NAT Overload)** — преобразование адресов с использованием портов.

В ходе работы необходимо построить корпоративную сеть с двумя отделами, внутренним веб-сервером и подключением к внешней сети.

# Часть 1. Справочник команд Cisco IOS

Используйте данный справочник при выполнении практической работы.

## 1. Основные команды маршрутизатора

| Команда | Назначение |
|---|---|
| `enable` | Переход в привилегированный режим |
| `configure terminal` | Переход в режим конфигурации |
| `interface gigabitEthernet 0/0` | Выбор интерфейса |
| `ip address` | Назначение IP-адреса интерфейсу |
| `no shutdown` | Включение интерфейса |
| `exit` | Выход из текущего режима |
| `end` | Возврат в привилегированный режим |
| `show ip interface brief` | Просмотр IP-адресов и состояния интерфейсов |
| `show running-config` | Просмотр текущей конфигурации |
| `copy running-config startup-config` | Сохранение конфигурации |

### Пример настройки интерфейса

```cisco
enable
configure terminal

interface gigabitEthernet 0/0
 ip address 192.168.1.1 255.255.255.0
 no shutdown
 exit

end
```

## 2. Статическая маршрутизация

Статическая маршрутизация позволяет вручную указывать маршрутизатору, через какое устройство необходимо отправлять пакеты в удалённую сеть.

### Добавление статического маршрута

```cisco
ip route 192.168.20.0 255.255.255.0 10.0.0.2
```

Общий синтаксис:

```text
ip route АДРЕС_СЕТИ МАСКА АДРЕС_СЛЕДУЮЩЕГО_УЗЛА
```

### Настройка маршрута по умолчанию

```cisco
ip route 0.0.0.0 0.0.0.0 10.0.0.2
```

Маршрут по умолчанию используется, если в таблице маршрутизации отсутствует более подходящий маршрут к сети назначения.

### Проверка маршрутов

```cisco
show ip route
```

## 3. NAT Inside и NAT Outside

Перед настройкой NAT необходимо определить внутреннюю и внешнюю стороны маршрутизатора.

**NAT Inside** — интерфейс, подключённый к внутренней сети.

```cisco
interface gigabitEthernet 0/0
 ip nat inside
 exit
```

**NAT Outside** — интерфейс, подключённый к внешней сети.

```cisco
interface gigabitEthernet 0/1
 ip nat outside
 exit
```

На одном маршрутизаторе может быть несколько внутренних интерфейсов NAT.

## 4. Static NAT

Static NAT создаёт постоянное соответствие между внутренним и внешним IP-адресами.

### Общий синтаксис

```cisco
ip nat inside source static ВНУТРЕННИЙ_IP ВНЕШНИЙ_IP
```

### Пример

```cisco
ip nat inside source static 192.168.1.10 203.0.113.3
```

Теперь внутреннему адресу `192.168.1.10` соответствует внешний адрес `203.0.113.3`.

### Удаление правила

```cisco
no ip nat inside source static 192.168.1.10 203.0.113.3
```

**Особенности Static NAT:**

- Постоянное соответствие адресов 1:1.
- Для каждого соответствия используется отдельный внешний IP-адрес.
- Может применяться для публикации внутренних серверов.

## 5. Dynamic NAT

Dynamic NAT автоматически выделяет свободный внешний IP-адрес из заранее настроенного пула.

### Создание пула

```cisco
ip nat pool PUBLIC_POOL 203.0.113.3 203.0.113.5 netmask 255.255.255.248
```

В данном примере пул содержит три IP-адреса.

### Создание ACL

```cisco
access-list 1 permit 192.168.1.0 0.0.0.255
```

ACL определяет, какие внутренние адреса разрешено преобразовывать.

`0.0.0.255` — wildcard mask для подсети `/24`.

### Включение Dynamic NAT

```cisco
ip nat inside source list 1 pool PUBLIC_POOL
```

### Удаление Dynamic NAT

```cisco
no ip nat inside source list 1 pool PUBLIC_POOL
no ip nat pool PUBLIC_POOL
```

**Особенности Dynamic NAT:**

- Использует пул внешних IP-адресов.
- Адреса выделяются автоматически.
- Количество одновременно используемых внешних адресов ограничено размером пула.
- Освободившийся адрес может использоваться другим компьютером.

## 6. PAT (NAT Overload)

PAT позволяет нескольким компьютерам использовать один внешний IPv4-адрес.

### Создание ACL

```cisco
access-list 1 permit 192.168.1.0 0.0.0.255
```

### Настройка PAT

```cisco
ip nat inside source list 1 interface gigabitEthernet 0/1 overload
```

**Разбор команды:**

- `ip nat inside source` — преобразование внутренних адресов источника.
- `list 1` — использование ACL 1.
- `interface gigabitEthernet 0/1` — использование IP-адреса выбранного внешнего интерфейса.
- `overload` — разрешение нескольким устройствам использовать один внешний IP.

### Удаление PAT

```cisco
no ip nat inside source list 1 interface gigabitEthernet 0/1 overload
```

## 7. Работа с несколькими ACL

Для разных внутренних сетей можно создавать отдельные ACL.

Пример:

```cisco
access-list 10 permit 192.168.10.0 0.0.0.255
access-list 20 permit 192.168.20.0 0.0.0.255
```

Каждую ACL можно использовать в отдельном правиле NAT.

В приведённом случае ACL определяет адреса, для которых выполняется NAT. Она не применяется для фильтрации пакетов на интерфейсе с помощью `ip access-group`.

## 8. Команды проверки и диагностики

| Команда | Назначение |
|---|---|
| `show ip nat translations` | Просмотр NAT-трансляций |
| `show ip nat statistics` | Статистика NAT |
| `show access-lists` | Просмотр ACL |
| `show ip route` | Просмотр таблицы маршрутизации |
| `show ip interface brief` | Проверка интерфейсов |
| `show running-config` | Просмотр настроек маршрутизатора |
| `clear ip nat translation *` | Очистка динамических NAT-трансляций |
| `ping IP_АДРЕС` | Проверка доступности узла |

Команды `show` и `clear` выполняются в привилегированном режиме `Router#`.

**Примечание:** динамические NAT-трансляции могут исчезать после истечения времени ожидания. Для проверки таблицы создайте сетевой трафик и сразу выполните `show ip nat translations`.

## 9. Проверка HTTP

Для включения HTTP-сервера в Cisco Packet Tracer:

1. Откройте сервер.
2. Перейдите во вкладку `Services`.
3. Выберите `HTTP`.
4. Установите `HTTP: On`.

Для открытия веб-страницы с компьютера:

1. Откройте компьютер.
2. Перейдите во вкладку `Desktop`.
3. Выберите `Web Browser`.
4. Введите IP-адрес сервера.

Пример:

```text
http://198.51.100.10
```

## Задание 1. Построение корпоративной сети

### Постановка задачи

Компания «ТехноСеть» открыла новый офис.

В организации работают два отдела:

- Бухгалтерия.
- Отдел разработки программного обеспечения.

Каждый отдел должен находиться в отдельной локальной сети.

Компания подключается к внешней сети через маршрутизатор провайдера.

Вам необходимо построить корпоративную сеть, настроить IP-адресацию и обеспечить маршрутизацию между её сегментами.

### 1.1. Топология сети

Постройте следующую топологию:

```text
   БУХГАЛТЕРИЯ                         ОТДЕЛ РАЗРАБОТКИ
  192.168.10.0/24                       192.168.20.0/24

   PC0      PC1                           PC2      PC3
    |        |                             |        |
    +---SW1--+                             +---SW2--+
        |                                      |
        | G0/0                           G0/1  |
        +---------------- R1 ------------------+
                          |
                         G0/2
                          |
                     10.0.12.0/30
                          |
                         G0/0
                          |
                       R2 (NAT)
                          |
                         G0/1
                          |
                    203.0.113.0/28
                          |
                         G0/0
                          |
                       R3 (ISP)
                          |
                         G0/1
                          |
                         SW3
                        /   \
                       /     \
                 Web Server  DNS Server
```

### 1.2. Необходимое оборудование

- 3 маршрутизатора Cisco 2911.
- 3 коммутатора Cisco 2960.
- 4 компьютера.
- 2 сервера.
- Соединительные кабели.

Названия устройств:

- `R1` — маршрутизатор внутренней сети.
- `R2` — маршрутизатор NAT.
- `R3` — маршрутизатор провайдера.
- `SW1` — коммутатор бухгалтерии.
- `SW2` — коммутатор разработки.
- `SW3` — коммутатор внешних серверов.

### 1.3. План IP-адресации

| Сегмент | Сеть | Маска |
|---|---|---|
| Бухгалтерия | `192.168.10.0/24` | `255.255.255.0` |
| Разработка | `192.168.20.0/24` | `255.255.255.0` |
| Соединение R1–R2 | `10.0.12.0/30` | `255.255.255.252` |
| Соединение R2–R3 | `203.0.113.0/28` | `255.255.255.240` |
| Внешние серверы | `198.51.100.0/24` | `255.255.255.0` |

### 1.4. Адресация маршрутизаторов

**Маршрутизатор R1**

| Интерфейс | IP-адрес | Маска | Подключение |
|---|---|---|---|
| G0/0 | `192.168.10.1` | `/24` | SW1 |
| G0/1 | `192.168.20.1` | `/24` | SW2 |
| G0/2 | `10.0.12.1` | `/30` | R2 G0/0 |

**Маршрутизатор R2**

| Интерфейс | IP-адрес | Маска | Подключение |
|---|---|---|---|
| G0/0 | `10.0.12.2` | `/30` | R1 G0/2 |
| G0/1 | `203.0.113.1` | `/28` | R3 G0/0 |

**Маршрутизатор R3**

| Интерфейс | IP-адрес | Маска | Подключение |
|---|---|---|---|
| G0/0 | `203.0.113.2` | `/28` | R2 G0/1 |
| G0/1 | `198.51.100.1` | `/24` | SW3 |

### 1.5. Адресация компьютеров

**Бухгалтерия**

| Устройство | IP-адрес | Маска | Шлюз |
|---|---|---|---|
| PC0 | `192.168.10.10` | `/24` | `192.168.10.1` |
| PC1 | `192.168.10.20` | `/24` | `192.168.10.1` |

**Отдел разработки**

| Устройство | IP-адрес | Маска | Шлюз |
|---|---|---|---|
| PC2 | `192.168.20.10` | `/24` | `192.168.20.1` |
| PC3 | `192.168.20.20` | `/24` | `192.168.20.1` |

### 1.6. Адресация внешних серверов

| Сервер | IP-адрес | Маска | Шлюз |
|---|---|---|---|
| Web Server | `198.51.100.10` | `/24` | `198.51.100.1` |
| DNS Server | `198.51.100.20` | `/24` | `198.51.100.1` |

### 1.7. Необходимо выполнить

1. Создайте топологию в Cisco Packet Tracer.
2. Разместите и соедините все устройства согласно схеме.
3. Назначьте IP-адреса всем компьютерам и серверам.
4. Укажите шлюзы по умолчанию.
5. Настройте IP-адреса на интерфейсах маршрутизаторов.
6. Включите все используемые интерфейсы.
7. На R1 настройте маршрут по умолчанию в сторону R2.
8. На R2 настройте статические маршруты к сетям бухгалтерии и разработки через R1.
9. На R2 настройте маршрут по умолчанию в сторону R3.
10. Проверьте доступность шлюзов с компьютеров обоих отделов.
11. Проверьте соединения между маршрутизаторами.
12. Проверьте передачу пакетов между бухгалтерией и отделом разработки.
13. Включите HTTP-сервис на внешнем Web Server.

**Важное условие:** на маршрутизаторе R3 не создавайте маршруты к частным сетям `192.168.10.0/24`, `192.168.20.0/24` и `172.16.10.0/24`.

Доступ к внешним серверам будет обеспечен после настройки NAT.

### 1.8. Проверка задания

Необходимо добиться успешного выполнения следующих проверок:

- PC0 → PC1.
- PC0 → PC2.
- PC2 → PC3.
- R1 → R2.
- R2 → R3.
- R3 → Web Server.

Для проверки можно использовать Ping.

### 1.9. Контрольные вопросы

1. Почему бухгалтерия и разработка находятся в разных подсетях?

3. Почему между R1 и R2 необходима маршрутизация?

## Задание 2. Настройка Static NAT для корпоративного сервера

### Постановка задачи

Компания решила разместить собственный корпоративный веб-сервер.

Сервер располагается во внутренней сети организации и использует частный IP-адрес.

При этом пользователи из внешней сети должны иметь возможность подключаться к нему по постоянному внешнему IP-адресу.

Необходимо настроить Static NAT.

### 2.1. Изменение топологии

Добавьте к маршрутизатору R2 отдельную серверную сеть.

```text
                    R2 (NAT)
                       |
                      G0/2
                       |
                      SW4
                       |
                 Company Server
```

Теперь R2 использует три интерфейса:

| Интерфейс | Назначение |
|---|---|
| G0/0 | Соединение с R1 |
| G0/1 | Соединение с R3 |
| G0/2 | Внутренняя серверная зона |

### 2.2. Адресация серверной зоны

Сеть:

```text
172.16.10.0/24
```

| Устройство | Интерфейс | IP-адрес | Маска |
|---|---|---|---|
| R2 | G0/2 | `172.16.10.1` | `255.255.255.0` |
| Company Server | FastEthernet0 | `172.16.10.10` | `255.255.255.0` |

Шлюз Company Server:

```text
172.16.10.1
```

Внешний IP-адрес корпоративного сервера:

```text
203.0.113.10
```

### 2.3. Правила NAT

На маршрутизаторе R2 необходимо определить следующие роли интерфейсов:

| Интерфейс | Роль NAT |
|---|---|
| G0/0 | NAT Inside |
| G0/1 | NAT Outside |
| G0/2 | NAT Inside |

При этом Static NAT должен создавать соответствие:

```text
Внутренний IP: 172.16.10.10
Внешний IP:    203.0.113.10
```

### 2.4. Необходимо выполнить

1. Добавьте коммутатор SW4.
2. Добавьте сервер Company Server.
3. Подключите SW4 к интерфейсу G0/2 маршрутизатора R2.
4. Подключите Company Server к SW4.
5. Настройте IP-адрес и маску сервера.
6. Настройте шлюз сервера.
7. Назначьте IP-адрес интерфейсу G0/2 маршрутизатора R2.
8. Включите интерфейс.
9. Включите HTTP-сервис на Company Server.
10. Настройте NAT Inside и NAT Outside на R2.
11. Создайте Static NAT для корпоративного сервера.
12. Проверьте доступность корпоративного сервера с R2.
13. С внешнего Web Server проверьте доступность внешнего адреса корпоративного сервера.
14. С внешнего Web Server откройте веб-страницу корпоративного сервера по адресу:

```text
http://203.0.113.10
```

15. Проверьте таблицу NAT на R2.

### 2.5. Ожидаемый результат

Внешний Web Server должен иметь возможность подключиться к Company Server через внешний адрес `203.0.113.10`.

При этом фактический IP-адрес Company Server остаётся `172.16.10.10`.

### 2.6. Контрольные вопросы

1. Почему для корпоративного сервера используется Static NAT?
2. Какой IP-адрес видит внешний пользователь?
3. Какой IP-адрес назначен самому серверу?
4. Почему серверу не обязательно иметь публичный IP-адрес на сетевом интерфейсе?
5. Почему для Static NAT необходимо постоянное соответствие адресов?

## Задание 3. Настройка Dynamic NAT для бухгалтерии

### Постановка задачи

Бухгалтерии компании необходим доступ к внешним веб-сервисам.

Провайдер предоставил организации два дополнительных внешних IPv4-адреса.

Компания решила, что компьютеры бухгалтерии будут автоматически получать свободные внешние адреса из общего пула.

Необходимо настроить Dynamic NAT.

### 3.1. Условия

Внутренняя сеть бухгалтерии:

```text
192.168.10.0/24
```

Пул внешних IP-адресов:

```text
203.0.113.5 – 203.0.113.6
```

Имя пула:

```text
ACCOUNTING_POOL
```

Маска внешней сети:

```text
255.255.255.240
```

Dynamic NAT должен распространяться только на бухгалтерию.

### 3.2. Требуемое преобразование

Пример возможного распределения:

| Компьютер | Внутренний IP | Внешний IP |
|---|---|---|
| PC0 | `192.168.10.10` | `203.0.113.5` |
| PC1 | `192.168.10.20` | `203.0.113.6` |

Адреса назначаются динамически, поэтому фактическое распределение может отличаться.

### 3.3. Необходимо выполнить

1. На R2 создайте отдельную ACL для сети бухгалтерии.
2. Используйте ACL с номером `10`.
3. Создайте пул `ACCOUNTING_POOL`.
4. Добавьте в пул два внешних IP-адреса.
5. Настройте Dynamic NAT на R2.
6. Убедитесь, что правило Static NAT корпоративного сервера осталось без изменений.
7. С PC0 отправьте Ping на внешний Web Server `198.51.100.10`.
8. С PC1 отправьте Ping на тот же сервер.
9. Откройте веб-страницу внешнего сервера с обоих компьютеров бухгалтерии.
10. На R2 проверьте таблицу NAT.
11. Определите, какие внешние IP-адреса используются PC0 и PC1.
12. Проверьте подключение к внешнему серверу с PC2 и PC3.
13. Объясните, почему компьютеры разработки пока не могут использовать Dynamic NAT бухгалтерии.

### 3.4. Дополнительный эксперимент

Добавьте третий компьютер в бухгалтерию.

Используйте следующую адресацию:

| Параметр | Значение |
|---|---|
| Устройство | PC4 |
| IP-адрес | `192.168.10.30` |
| Маска | `255.255.255.0` |
| Шлюз | `192.168.10.1` |

Подключите PC4 к SW1.

Попробуйте обратиться с PC4 к внешнему Web Server.

Перед проверкой убедитесь, что оба адреса пула заняты активными трансляциями PC0 и PC1.

Если трансляции уже завершились, повторно создайте трафик и проверьте таблицу NAT.

## Задание 4. Настройка PAT для отдела разработки

### Постановка задачи

В отделе разработки работает несколько сотрудников.

Компания не хочет выделять каждому разработчику отдельный внешний IP-адрес.

Необходимо обеспечить доступ всех компьютеров отдела разработки к внешним ресурсам через один внешний IP-адрес.

Для этого используйте PAT (NAT Overload).

### 4.1. Условия

Внутренняя сеть разработки:

```text
192.168.20.0/24
```

Внешний IP-адрес маршрутизатора R2:

```text
203.0.113.1
```

Интерфейс R2 для PAT:

```text
GigabitEthernet0/1
```

ACL для отдела разработки:

```text
20
```

Для настройки необходимо использовать ключевое слово:

```cisco
overload
```

### 4.2. Требуемое преобразование

Компьютеры отдела разработки должны использовать один внешний IP-адрес:

| Компьютер | Внутренний IP | Внешний IP |
|---|---|---|
| PC2 | `192.168.20.10` | `203.0.113.1` |
| PC3 | `192.168.20.20` | `203.0.113.1` |

При этом маршрутизатор должен различать соединения компьютеров с помощью PAT.

### 4.3. Необходимо выполнить

1. На R2 создайте отдельную ACL для сети разработки.
2. Используйте ACL с номером `20`.
3. Настройте PAT для отдела разработки.
4. В качестве внешнего адреса используйте IP интерфейса G0/1 маршрутизатора R2.
5. Убедитесь, что Static NAT корпоративного сервера продолжает работать.
6. Убедитесь, что Dynamic NAT бухгалтерии продолжает работать.
7. С PC2 отправьте Ping на внешний Web Server.
8. С PC3 отправьте Ping на тот же сервер.
9. Откройте с PC2 и PC3 веб-страницу:

```text
http://198.51.100.10
```

10. На R2 выполните:

```cisco
show ip nat translations
show ip nat statistics
```

11. Найдите NAT-трансляции компьютеров отдела разработки.
12. Определите внешний IP-адрес, который используют PC2 и PC3.
13. Сравните таблицы трансляций Dynamic NAT и PAT.

### 4.4. Дополнительное задание

Добавьте в отдел разработки ещё два компьютера:

- PC5.
- PC6.

Самостоятельно выберите для них свободные IP-адреса из сети:

```text
192.168.20.0/24
```

Подключите оба компьютера к SW2.

Настройте IP-адреса, маски и шлюзы.

Не изменяя конфигурацию PAT, проверьте доступ новых компьютеров к внешнему Web Server.

### 4.5. Контрольные вопросы

1. Почему PAT позволяет использовать один внешний IP-адрес нескольким компьютерам?

# Часть 3. Итоговая топология

После выполнения всех четырёх заданий сеть должна иметь следующую структуру:

```text
     БУХГАЛТЕРИЯ                         ОТДЕЛ РАЗРАБОТКИ
    192.168.10.0/24                       192.168.20.0/24
       Dynamic NAT                               PAT

     PC0   PC1   PC4                      PC2   PC3   PC5   PC6
      |     |     |                        |     |     |     |
      +---- SW1 ---+                       +----- SW2 ------+
            |                                     |
           G0/0                                 G0/1
            |                                     |
            +---------------- R1 -----------------+
                              |
                             G0/2
                              |
                         10.0.12.0/30
                              |
                             G0/0
                              |
                          R2 (NAT) ---- G0/2 ---- SW4
                              |                     |
                             G0/1              Company Server
                              |                 172.16.10.10
                         203.0.113.0/28         Static NAT
                              |                 203.0.113.10
                             G0/0
                              |
                           R3 (ISP)
                              |
                             G0/1
                              |
                             SW3
                            /   \
                           /     \
                    Web Server   DNS Server
                   198.51.100.10 198.51.100.20
```

## Итоговое распределение NAT

| Сеть или устройство | Тип NAT | Внешний IP-адрес |
|---|---|---|
| Company Server | Static NAT | `203.0.113.10` |
| Бухгалтерия | Dynamic NAT | `203.0.113.5–203.0.113.6` |
| Отдел разработки | PAT | `203.0.113.1` |

**Важно:** все три вида NAT должны одновременно работать на маршрутизаторе R2.
