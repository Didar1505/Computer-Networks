# Шпаргалка: ACL и межсетевые экраны в Cisco Packet Tracer

| ------------- | ----------------- | ------------- |
| PC0           | `192.168.1.10/24` | `192.168.1.1` |

## 2. Основные сетевые протоколы и порты

| Протокол          | Порт       | Назначение                        |
| ----------------- | ---------- | --------------------------------- |
| FTP               | TCP 21     | Управляющее соединение FTP        |
| FTP Data (Active) | TCP 20     | Передача данных в активном FTP    |
| SSH               | TCP 22     | Защищённое удалённое управление   |
| Telnet            | TCP 23     | Незащищённое удалённое управление |
| SMTP              | TCP 25     | Отправка электронной почты        |
| DNS               | UDP/TCP 53 | Преобразование доменных имён      |
| DHCP Server       | UDP 67     | Выдача IP-адресов                 |
| DHCP Client       | UDP 68     | Получение IP-адресов              |
| HTTP              | TCP 80     | Незашифрованный веб-доступ        |
| POP3              | TCP 110    | Получение электронной почты       |
| NTP               | UDP 123    | Синхронизация времени             |
| IMAP              | TCP 143    | Доступ к электронной почте        |
| HTTPS             | TCP 443    | Защищённый веб-доступ             |
| RDP               | TCP 3389   | Удалённый рабочий стол            |
| ICMP              | Нет портов | Ping и диагностические сообщения  |

Важно: ICMP не использует TCP/UDP-порты. Поэтому для блокировки Ping применяется `deny icmp`, а не `eq 80` или `eq 443`.

FTP также может использовать отдельные соединения для передачи данных. Запрет TCP-порта 21 блокирует установление обычной FTP-сессии, но не является универсальным запретом всех возможных способов передачи файлов.

## 3. Основные команды ACL

### Создание правила

```
access-list 110 deny tcp any any eq 80
```

Запретить TCP-трафик к порту назначения 80.

### Разрешение трафика

```
access-list 110 permit ip any any
```

Разрешить любой IPv4-трафик, который дошёл до этого правила.

### Запрет Ping

```
access-list 110 deny icmp any any
```

Запретить весь ICMP-трафик, совпадающий с этим правилом.

### Фильтрация по конкретному компьютеру

```
access-list 110 deny ip host 192.168.1.40 any
```

Запретить весь IPv4-трафик от Laptop0.

### Фильтрация между двумя устройствами

```
access-list 110 deny icmp host 192.168.1.10 host 192.168.2.10
```

Запретить ICMP от PC0 к Server0.

### Фильтрация по подсети

```
access-list 110 deny tcp 192.168.1.0 0.0.0.255 host 192.168.3.10 eq 21
```

Запретить FTP от всей пользовательской сети к Server1.

## 4. Что означают ключевые слова?

| Команда       | Значение                                                                                        |
| ------------- | ----------------------------------------------------------------------------------------------- |
| `permit`      | Разрешить совпавший трафик                                                                      |
| `deny`        | Запретить совпавший трафик                                                                      |
| `ip`          | Любой IPv4-трафик                                                                               |
| `tcp`         | TCP-трафик                                                                                      |
| `udp`         | UDP-трафик                                                                                      |
| `icmp`        | ICMP-трафик, включая Ping                                                                       |
| `host`        | Один конкретный IP-адрес                                                                        |
| `any`         | Любой адрес                                                                                     |
| `eq`          | Равно указанному порту                                                                          |
| `gt`          | Порт больше указанного значения                                                                 |
| `lt`          | Порт меньше указанного значения                                                                 |
| `range`       | Диапазон портов                                                                                 |
| `established` | Для TCP — пакеты с установленными ACK или RST; не полноценное отслеживание состояния соединения |

## 5. Как применять ACL к интерфейсу

Сначала перейдите в режим настройки:

```
enable
configure terminal
```

Выберите интерфейс:

```
interface gigabitEthernet 0/1
```

Примените ACL в исходящем направлении:

```
ip access-group 110 out
```

Или во входящем направлении:

```
ip access-group 110 in
```

Выйдите из режима настройки:

```
end
```

Запомните:

- `in` — пакет входит в маршрутизатор через выбранный интерфейс.
- `out` — пакет выходит из маршрутизатора через выбранный интерфейс.

Например, ACL на `G0/1 out` фильтрует пакеты, выходящие из маршрутизатора в сеть Server0.

## 6. Порядок правил — самое важное

ACL проверяется сверху вниз. Первое совпавшее правило определяет действие.

Неправильно:

```
access-list 110 permit ip any any
access-list 110 deny tcp host 192.168.1.40 host 192.168.2.10 eq 80
```

Первое правило разрешает весь IPv4-трафик, поэтому запрет HTTP не сработает.

Правильно:

```
access-list 110 deny tcp host 192.168.1.40 host 192.168.2.10 eq 80
access-list 110 permit ip any any
```

Также помните о неявном запрете в конце ACL: если пакет не совпал ни с одним правилом, он блокируется.

## 7. Команды проверки и диагностики

| Команда                                 | Для чего нужна                                 |
| --------------------------------------- | ---------------------------------------------- |
| `show access-lists`                     | Посмотреть правила ACL и счётчики              |
| `show ip interface gigabitEthernet 0/1` | Проверить применение ACL к интерфейсу          |
| `show running-config`                   | Посмотреть текущую конфигурацию                |
| `show ip interface brief`               | Проверить состояние интерфейсов и их IP-адреса |
| `ping 192.168.2.10`                     | Проверить доступность Server0                  |
| `tracert 192.168.2.10`                  | Посмотреть маршрут с ПК                        |
| `ftp 192.168.3.10`                      | Подключиться к FTP-серверу                     |

Для проверки HTTP откройте на ПК Desktop → Web Browser и введите `http://192.168.2.10`.

## 8. Как удалить и изменить ACL

Удалить весь нумерованный ACL:

```
configure terminal
no access-list 110
```

После этого его можно создать заново с правильным порядком правил.

Чтобы применить новый ACL, не забудьте назначить его интерфейсу через `ip access-group`.

Чтобы снять ACL с интерфейса, не удаляя сам список:

```
interface gigabitEthernet 0/1
no ip access-group 110 out
```

## 9. Алгоритм выполнения практической работы

1. Проверьте IP-адреса, маски, шлюзы и состояние интерфейсов.
2. Убедитесь, что серверы работают и нужные службы включены.
3. Определите, какой источник, назначение, протокол и порт необходимо разрешить или запретить.
4. Составьте правила ACL, размещая конкретные условия перед общими.
5. Примените ACL к правильному интерфейсу и направлению.
6. Проверьте разрешённый и запрещённый трафик.
7. Выполните `show access-lists` и объясните результаты.

Главное правило: недостаточно написать ACL — необходимо правильно определить направление трафика, порядок правил и интерфейс, к которому применяется список.
