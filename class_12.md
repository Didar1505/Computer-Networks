# Практическая работа: «Настройка политики безопасности сети организации»

## 1. Новая топология

## [Шапргалка по выполнению практических задач](https://github.com/Didar1505/Computer-Networks/blob/main/Class_12_cheat_sheet.md)

Постройте сеть организации в Cisco Packet Tracer. Для маршрутизации используйте **Cisco 2911** с тремя интерфейсами GigabitEthernet. Разделите сеть на три подсети:

- Пользовательская сеть — `192.168.1.0/24`
- Сеть веб-сервера — `192.168.2.0/24`
- Сеть FTP-сервера — `192.168.3.0/24`

Подключите PC0, PC1, PC2 и Laptop0 к одному коммутатору пользовательской сети. Server0 и Server1 подключите к отдельным коммутаторам, каждый из которых соединён с соответствующим интерфейсом маршрутизатора.

## 2. Оборудование и IP-адресация

| Устройство | IP-адрес | Шлюз по умолчанию |
|---|---|---|
| PC0 | `192.168.1.10/24` | `192.168.1.1` |
| PC1 | `192.168.1.20/24` | `192.168.1.1` |

На Server0 включите HTTP. На Server1 включите FTP и настройте учётную запись пользователя с разрешением на чтение файлов.

Перед выполнением заданий убедитесь, что устройства имеют правильные IP-адреса и шлюзы, интерфейсы маршрутизатора активны, а компьютеры могут обмениваться трафиком с серверами.

## 3. Практические задания

### Задание 1. Защита FTP-сервера

**Сложность: лёгкая**

Сотрудники должны иметь доступ к веб-сайту организации, но не должны подключаться к FTP-серверу.

**Условия:**
- Запретите FTP-трафик от пользовательской сети к Server1.
- Разрешите HTTP-доступ к Server0.
- Разрешите Ping до обоих серверов.
- Остальной трафик, не запрещённый правилами, должен оставаться разрешённым.

**Проверка:**
1. Попробуйте подключиться к FTP-серверу с PC0.
2. Откройте веб-страницу Server0.
3. Выполните Ping до обоих серверов.
4. Проверьте счётчики правил с помощью `show access-lists`.

**Цель:** научиться фильтровать трафик по TCP-порту и применять разные правила к разным серверам.

### Задание 2. Доступ к веб-серверу только для администратора

**Сложность: средняя**

Только PC2 (`192.168.1.30`) должен иметь доступ к веб-серверу Server0.

**Условия:**
- PC2 может открывать веб-страницу Server0.
- PC0, PC1 и Laptop0 не могут обращаться к веб-серверу.
- Доступ к FTP-серверу этим правилом не ограничивается.

**Проверка:**
1. Откройте веб-страницу Server0 с PC2.
2. Повторите попытку с PC0, PC1 и Laptop0.
3. Убедитесь, что доступ к FTP-серверу не изменился.

**Цель:** научиться фильтровать трафик по IP-адресам источника и назначения.

### Задание 3. Веб-сервер работает только по HTTPS

**Сложность: средняя**

Администратор решил отключить незашифрованный HTTP-доступ к веб-серверу.

**Условия:**
- Разрешите TCP-порт 443 к Server0.
- Запретите TCP-порт 80 к Server0.
- Запретите остальной IPv4-трафик к Server0.
- Не изменяйте правила доступа к FTP-серверу.

**Проверка:**
1. Убедитесь, что HTTP-доступ блокируется.
2. Проверьте правило разрешения TCP-порта 443.
3. Убедитесь, что доступ к FTP-серверу работает согласно прежней политике.

Для проверки HTTPS соответствующий сервис должен быть настроен на Server0. Если используемая версия Packet Tracer не поддерживает полноценную проверку HTTPS, подтвердите результат анализом ACL и его счётчиков.

**Цель:** научиться создавать несколько правил для одного назначения и учитывать порядок их обработки.

### Задание 4. Запрет доступа для конкретного устройства

**Сложность: средняя**

Laptop0 (`192.168.1.40`) временно лишён доступа к серверам из-за нарушения политики безопасности.

**Условия:**
- Запретите Laptop0 доступ к Server0 и Server1.
- Остальные компьютеры должны сохранять прежний доступ.
- Не блокируйте трафик Laptop0 к другим адресам.

**Проверка:**
1. Попробуйте обратиться с Laptop0 к обоим серверам.
2. Повторите проверки с PC0 и PC2.
3. Убедитесь, что остальные устройства не потеряли доступ к серверам.

**Цель:** научиться вводить точечные ограничения для отдельных устройств без блокировки всей пользовательской сети.

### Задание 5. Разделение пользовательской и серверной сетей

**Сложность: повышенная**

Организация решила установить отдельные правила доступа к внутренним ресурсам.

**Политика безопасности:**
- PC0 и PC1 могут использовать веб-сервер.
- PC2 может использовать веб-сервер и FTP-сервер.
- Laptop0 не может обращаться ни к одному серверу.
- Остальной трафик, не затронутый указанной политикой, должен оставаться разрешённым.

**Задачи:**
1. Самостоятельно составьте расширенный ACL.
2. Определите, на каких интерфейсах и в каком направлении необходимо применить правила.
3. Соблюдайте правильный порядок правил.
4. Проверьте доступность сервисов с каждого устройства.
5. Используйте `show access-lists` для проверки счётчиков.

**Цель:** научиться проектировать комплексную политику доступа и учитывать взаимодействие нескольких правил ACL.

### Задание 6. Найдите ошибку в конфигурации

**Сложность: аналитическая**

Преподаватель предоставляет следующую конфигурацию ACL:

```text
access-list 110 permit ip any any
access-list 110 deny tcp host 192.168.1.40 host 192.168.2.10 eq 80
```

**Задачи:**
1. Объясните, почему запрет HTTP для Laptop0 не срабатывает.
2. Исправьте порядок правил.
3. Проверьте результат в Cisco Packet Tracer.
4. Объясните, почему правила ACL обрабатываются сверху вниз.

**Цель:** научиться анализировать чужую конфигурацию, находить логические ошибки и исправлять их.

## 4. Требования к отчёту

Для каждого выполненного задания предоставьте:

1. Цель задания.
2. Конфигурацию ACL.
3. Скриншот топологии сети.
4. Скриншоты результатов проверки разрешённых и запрещённых соединений.
5. Вывод команды `show access-lists`.
6. Краткое объяснение того, почему каждый проверенный тип трафика разрешён или заблокирован.

**Важно:** перед выполнением каждого задания проверьте существующие ACL. Если работа начинается с чистой конфигурации, удалите предыдущие правила и настройте новые. В заданиях с несколькими политиками доступа сохраняйте все необходимые разрешения и запреты.

Работа считается выполненной, если студент не только демонстрирует команды, но и объясняет логику правил, порядок их обработки и выбранное направление применения ACL.
